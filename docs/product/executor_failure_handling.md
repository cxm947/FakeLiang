# 执行器 · 失败七分类处理表（简化版主体 v1）

> 来源：跨模型评审（2026-10-01，8 轮问答）· **结论：规则输入齐全，可以动手实现**。
> 本文是"本轮简化主体"的验收基线；文末列出**明确暂缓**的连接点（每项都有当前处理出口，不留悬空项）。

## 0. 总体判据

- 核验判定接口**仍是二值**（成功 / 没成功）；三种汇总状态属于核验明细。
- 一个步骤最多 **三次真实尝试**；**成功立即返回**，不补足三次。
- 退出码：**0** 全部通过；**1** 合法全结案但含失败/超时/依赖阻塞；**2** 未闭合或中止。
- 缺口与普通失败**分开记账**；缺口不因时间经过自动改写成失败或超时。

## 1. 七类处理表

| 类别 | 谁处理 / 依据什么继续 | 是否占真实尝试 | 何时停止 | 最终记录 |
|---|---|---|---|---|
| **1 信息不足** | 执行器记录缺失的运行参数/环境信息/必要检查结果 + 已检查证据，交回规划器 | 不增加；保留此前已消耗次数 | 自主检查后仍不足即停，**本轮不恢复** | `WAITING_INPUT`、`NEXT_RUN_ONLY`、`terminal_result=null`；阻断性缺口，不计合法结案 |
| **2 前提不满足** | 执行器 **pre** 检查；**每个规定检查项一次**；全部通过才进入实施 | 不占 | 任一必要条件明确不满足即交回；**本轮无修复、无重新入选** | `PRECONDITION_BLOCKED`；不记方法失败；只有具备既定"结构不可达"证据才可合法阻塞结案，否则保持未闭合 |
| **3 会话不可用** | **会话管理器**负责供给与恢复；执行器只按提供的会话描述 + 已有证据**判定是否匹配本实现**，不额外探测 | 确定未启动不占；已启动后的故障不抹掉次数 | 开工前不匹配/不可用即交回；实施中失联转第 4 类 | `SESSION_UNAVAILABLE`（原因 + 会话引用）；未实施不记方法失败；环境缺口未解决 → 未闭合 |
| **4 工具执行异常** | 执行器按已有派发记录与返回分类，程序记账；**不主动核对原调用** | 确定未启动不占；确定已启动计入；**启动未知占住当前尝试槽位** | 未启动的适配错误记录并交回，不新增自修复循环；已启动且明确失败转第 5 类；结果未知**不重发**，到原截止时间停止 | 未启动且无法继续 → 工具/适配缺口；未知到期 → `TIMED_OUT`，同时保留"原执行状态未知" |
| **5 方法未奏效** | 执行器依据执行反馈与 post 结果，在**同一目标、同一指定方法**内调整或选择合格实现 | 每次真实完整实施计一次；链内多段调用不拆开 | 成功立即停；三次均未成功停；截止时间先到停 | `SUCCEEDED / FAILED / TIMED_OUT`；部分成果与失败原因保留 |
| **6 核验未通过** | 核验器按子目标判据核验；执行器可用**整个验证会话唯一一次**补证；补证后仍非 `ALL` → 转第 5 类 | 核验、补证、复核**不增加**真实尝试 | 达到 `ALL` 即成功；无补证额度或无可补证据即结束本次核验，**不循环补采** | 本次 `NOT_SUCCEEDED`（不自动成为步骤终局）；**目标/实现契约缺口单列**，不冒充普通方法失败 |
| **7 预算耗尽** | 程序按持久化计数与原截止时间执行限制 | 不创造额外尝试、不把未启动动作凑成次数 | 三次均未成功；或仍在执行/等待结果的步骤到期 | 前者 `FAILED`，后者 `TIMED_OUT`；已报告的信息/前提/供给缺口**不因时间经过改写成超时** |

**第 7 类底线**：若既有设施另有硬调用上限，导致"不足三次、也未到截止时间"就无法继续 → 只记**预算中断、未完成**，不得伪造 `FAILED`。

## 2. 核验（post）判定模型

核验目标 = 该必做步骤在**对应版本的原始依赖图**里对应的**若干子聚合目标**（判据类型约 4–5 种，不等于每个步骤都有 4–5 个目标）。

| 汇总 | 判定 | 核验器二值结论 |
|---|---|---|
| `ALL` | 所有必需子目标都有满足判据的证据 | 成功 |
| `PARTIAL` | 至少一个已满足、未全部满足 | 没成功 |
| `NONE` | 没有任何必需子目标被证明满足 | 没成功 |

至少记录：`required_goal_ids` / `satisfied_goal_ids` / `missing_goal_ids`（并区分"证据明确未满足"与"证据不足"）/
`evidence_refs` / `reason_hypotheses`（无依据就写"原因未明"，不编造因果）/ `validation_id / attempt_id / graph_revision`。

**补证**：`supplement_used` 按**整个验证会话**持久化，最多 `false → true` 一次；恢复不重置；启动即扣除，失败也不补回；
初次核验不算补证；补证只能**收集/取回/整理已有尝试产生的证据**，重新实施目标动作必须计为新尝试。

`NONE` 只表示本次没证明成立，**不等于永久不可能**。

## 3. 明确暂缓（每项都有当前出口）

| 暂缓项 | 主体里的当前处理 |
|---|---|
| 局部修复（pre 阶段改环境） | pre 只检查，失败交回 |
| "部分满足 → 推因 → 定向续作一次" | 只记录部分成果与原因假设，不执行该分支 |
| 会话探活 / 恢复 / 等价替换策略 | 留给**会话管理器**契约 |
| 执行器额外的会话资格探测 | 不新增，消费提供方记录 |
| 原调用主动核对 | 不查询；未知动作不重发，按原截止时间收敛 |
| 前提阻塞后的重新入选 | 本轮不设；异常提前选点如实留下未闭合结果 |

## 4. 实施顺序（本轮主体）

1. **记录模型与计数**：验证会话 / 真实尝试 / 启动状态 / 补证额度 / 终局，全部支持持久化恢复。
2. **接入 pre 与绑定处理**：检查项一次执行；前提阻塞、信息不足、会话不可用分别记录；**不加派发前提守卫**。
3. **执行阶段分类**：未启动 / 已启动 / 启动未知；未知动作禁止重发；截止时间不重置。
4. **post 子目标核验**：输出 `ALL/PARTIAL/NONE` 明细，保留二值结论；补证按整个会话扣一次。
5. **接回三次完整尝试与收尾**：成功立即返回；三次均未成功才失败；活动步骤到期超时；缺口单列。
6. **规划接口回归 + 真机跑**：暂缓功能保持**未启用**，不在主体里顺手补做。

## 5. 交付前必须钉住的断言

- [ ] 第一次成功不会强行跑满三次。
- [ ] 第一轮用掉补证后，第二/三轮以及恢复运行都不能再补证。
- [ ] `PARTIAL` 不被记成成功、不触发定向续作、也不获得第四次机会。
- [ ] 未启动不算真实尝试；"启动未知"不伪记启动，也不能释放槽位重发。
- [ ] pre 不循环；信息不足本轮不恢复。
- [ ] 缺口与普通失败分开；退出码 **0 / 1 / 2** 与闭合、缺口一致。

## 6. 实现所需配置（从现有图与目录取得，不需要再讨论抽象规则）

- 子目标类型 + 步骤 → 必需子目标的映射；- 每类目标的现有核验判据；- 每个步骤允许的实现集合；- 原步骤时限。
- 缺映射/缺判据 → **报契约缺口**，不得自行猜一个判据让它通过。
