# 前置与后置技能卡规范

本文件放在 docs/product/，作为现行卡片编写与装载约定；本批只规定前置族和后置族，处理族另批制定。与旧 skill_contract.md 中的旧 JSON 输入、判据或装订器说明冲突时，本文件在本批范围内优先；不能据此声称旧执行机制已经重新接线。

卡片给模型方法、输入来源和证据判据，模型依现场选择动作。引擎负责输出形状、位置绑定、派发、资源归属、回执及引用核验。卡片不重新定义这些协议。

## 两份文件的唯一职责

| 位置 | 给谁 | 本批职责 |
| --- | --- | --- |
| skill.json.allowed_tools | 给代码，同时展示给模型 | 唯一的类别许可声明；装载器读取，调用与结束答复入口执行检查。 |
| SKILL.md 前言 | 给代码，同时展示给模型 | 保留现有身份、输入来源、位置及节点绑定；新卡不再声明 tools。 |
| SKILL.md 正文 | 给模型 | 手写检查对象、适用条件、方法、正反证据与未确认情形；代码不从正文抽取判据。 |
| 装载结果 tools | 给代码，同时展示给模型 | allowed_tools 的兼容投影，由代码生成，不是另一份可编辑声明。 |
| 运行层上下文与回执 | 给模型；代码核对归属和边界 | 提供已有会话、执行位置、工具、HTTP 基址、材料引用及本次可引用的原文；不写死在卡里。 |

有 allowed_tools 时，以它为准，不能与前言 tools 求并集。未迁移卡没有该字段时，继续使用原前言 tools；它的其他行为不在本批变更。JSON 字段存在但非法必须拒绝，不能退回旧声明。除 allowed_tools 外，本批不把旧 JSON 的 input、output、judge 等键重新接入执行语义。

allowed_tools 使用引擎现有七类：cmd、pws、tool、code、msf、http、finish。卡片只列实际需要的子集，不自行定义别名或 JSON 形状；本批前三卡不需要原生控制台动作，因此只声明 cmd、tool、必要时 http，以及 finish。stage 是未迁移卡的旧入口，本规范不把它列为新的答复类别。本批不改现有类别常量及名称。

许可列表必须非空、无重复且全部为有效类别名。类别未允许时，派发前给出 LEAN_TOOL_UNDECLARED，包含卡片 ID、请求类别及允许列表；finish 同样检查，不能绕过。有效许可变化必须改变卡片摘要；未消费的旧 JSON 字段不能偷偷改变权限。

## 身份、TTP 与最小参数

卡的语义身份是被检查步骤的 TTP 与具体问题项或效果；id 是现有目录定位标识，不据此推造 TTP。when.technique 指被检查 AND 步骤在图上的 job_id，不指检查工具自己的技术编号。已声明的值必须参与原有精确匹配，不能变成模糊加分项。

图上没有 TTP 就不填。当前前言解析器不接受空字符串或 null，因此以省略 when.technique 表示未声明；若 when 没有其他条件，也省略整个 when。不得补猜一个编号，不得把缺失值描述成已经通过 TTP 核验。本批不改 when 的匹配方式，不增加 TTP 推断，也不按卡片 ID 或节点编号分叉。

只声明方法实际需要的输入。预期事实来自任务，执行位置、工具及访问材料来自运行层；不能把任务中的假设或已有 observed_* 字段直接当成这次证据。访问材料必须已经存在。卡片不增加无依据的默认端口、超时、重试次数、睡眠间隔或输出阈值。

## 前置族字段表

| 字段或正文约定项 | 位置 | 给谁 | 必须 | 合格条件 |
| --- | --- | --- | --- | --- |
| name | 前言 | 给代码 | 是 | 保留现有发布名与目录对应关系。 |
| id | 前言 | 给代码 | 是 | 保留现有业务 ID，不由模型改写。 |
| description | 前言 | 给模型；代码检查结构 | 是 | 说明核对哪类前提及主要限制，不预告成功。 |
| kind | 前言 | 给代码 | 是 | 前置族沿用 recon，不另造阶段枚举。 |
| runs_at | 前言 | 给代码 | 是 | 使用既有 base 或 position，模型不能借正文改执行位置。 |
| delivers | 前言 | 给代码，同时给模型 | 是 | 声明交付类型，不表示本次已经交付。 |
| inputs | 前言 | 给代码，同时给模型 | 是 | 逐项声明 from 及必要的 optional；不重复旧 JSON 输入表。 |
| allowed_tools | skill.json | 给代码，同时给模型 | 是 | 声明所需动作与 finish；新卡不保留前言 tools。 |
| when | 前言 | 给代码 | 有实际条件时 | 使用现有 case、service、technique；不补假值，不写主机名或节点编号特例。 |
| fact_subject | 正文「何时用」 | 给模型 | 是 | 明确任务谓词或判据类别，以及要核对的目标、来源位置、主体或命名空间。 |
| required_context | 正文「何时用」 | 给模型 | 是 | 说明需要哪些已提供事实和材料，缺少哪些信息便不能判断。 |
| observation_method | 正文「怎么做」 | 给模型 | 是 | 手写该前提如何在现场观察、每条方法何时适用，以及需要读回什么。 |
| true_evidence | 正文「怎么判」 | 给模型 | 是 | 说明哪些本次原文足以支持该前提，以及证据覆盖的范围。 |
| false_evidence | 正文「怎么判」 | 给模型 | 是 | 说明哪些直接反证足以否定该前提；没有可用反证方法时明确写出限制。 |
| uncertain_cases | 正文「怎么判」 | 给模型 | 是 | 说明缺输出、错误位置、权限不足、信息不全或证据冲突时如何保留未确认。 |
| misleading_signals | 正文「怎么判」 | 给模型 | 是 | 点明这项检查中看起来像成功却不能证明前提的具体信号。 |
| citation_requirement | 正文「怎么判」 | 给模型；代码核验引用 | 是 | 要求本次可引用回执、准确调用归属及逐字引文；缺证据记 uncertain。 |

正文约定项是写作要求，不是新增前言键，也不是另一份由代码解析的判据对象。每张合格前置卡至少具备表中全部必填项；不能只留下参数表或通用执行纪律。

## 后置族字段表

| 字段或正文约定项 | 位置 | 给谁 | 必须 | 合格条件 |
| --- | --- | --- | --- | --- |
| name | 前言 | 给代码 | 是 | 保留现有发布身份。 |
| id | 前言 | 给代码 | 是 | 保留现有业务 ID。 |
| description | 前言 | 给模型；代码检查结构 | 是 | 说明检查哪一种实际效果，不把命令完成写成效果达成。 |
| kind | 前言 | 给代码 | 是 | 后置族沿用 validation。 |
| runs_at | 前言 | 给代码 | 是 | 使用既有位置绑定，不按输出里的主机名重新选位置。 |
| delivers | 前言 | 给代码，同时给模型 | 是 | 使用现有交付类型，声明本身不是证据。 |
| inputs | 前言 | 给代码，同时给模型 | 是 | 只列此效果观察实际需要的任务与运行层输入。 |
| allowed_tools | skill.json | 给代码，同时给模型 | 是 | 声明观察动作及 finish，不重复引擎输出 schema。 |
| when | 前言 | 给代码 | 有实际条件时 | 绑定被检查的 AND；technique 的身份与空值规则同前置族。 |
| effect_subject | 正文「何时用」 | 给模型 | 是 | 指明检查本步哪个子 OR 事实或哪类效果，保留其主体和变量绑定。 |
| required_context | 正文「何时用」 | 给模型 | 是 | 说明要用的目标、会话、产物或主体及它们与本步的关系；不把创建声明当成效果存在。 |
| observation_method | 正文「怎么做」 | 给模型 | 是 | 说明如何直接观察效果；处理动作的退出码不代替后置观察。 |
| true_evidence | 正文「怎么判」 | 给模型 | 是 | 说明支持该子 OR 成立所需的实际状态及原文证据。 |
| false_evidence | 正文「怎么判」 | 给模型 | 是 | 说明哪些当前状态与目标效果直接矛盾；未观察到不自动等于不存在。 |
| uncertain_cases | 正文「怎么判」 | 给模型 | 是 | 包括无回读、错对象、陈旧状态、局部可见、证据缺失和互相冲突。 |
| misleading_signals | 正文「怎么判」 | 给模型 | 是 | 列出本效果的具体假象，例如只有执行成功、登记行或自报标记。 |
| proof_scope | 正文「怎么判」 | 给模型 | 是 | 明确检查整体还是局部；只观察到子条件不得宣布整个终点成立。 |
| citation_requirement | 正文「怎么判」 | 给模型；代码核验引用 | 是 | 每项结论使用本次允许引用的原文；不能用前置结论或其他节点记录冒充后置观察。 |

每张合格后置卡至少具备上述必填项。模型可说明多个子事实的状态，但不得从一个局部成功推定所有子 OR 成立；运行层的终点证据核验不由卡片关闭。本批仅制定后置规范，不改写现有后置卡。

## 正文与答复纪律

正文固定采用「何时用」「怎么做」「怎么判」三个主段，细项可用三级标题展开。每张卡的方法必须针对实际观察对象手写，说明如何看到事实、什么才算数、什么看着像却不算数。

一次作答只提交一个引擎动作；多步方法要分成多次作答，并在每次回执后决定下一步。卡片不提供 actions 批次，也不规定前置必须一条命令完成。既有引擎协议的解析和行为不在本批重写。

结论使用引擎既有 finish 字段与枚举。引文必须逐字出现在本次可引用回执中，不能折叠空白、去掉转义后重新拼成原文，也不能将退出码 0、执行完成或脚本打印 SUCCESS 当成目标事实。unknown、已 abandon、其他节点或无法核对归属的来源，不用于证明本次条件；没有有效证据记 uncertain。

这份规范不新增输出 JSON 形状，不接入新的事实判定程序，也不改变会话迁移、探活、资源占用、调度、重试或预算。正文约束与已有引擎证据闸门的实际实现要分别验收，不能因为卡片门禁通过就声称真环境验证通过。
