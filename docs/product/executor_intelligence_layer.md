# 执行器 · 智能层方案（v1）

> 来源：跨模型评审 2026-10-01（9 轮）。**结论：可直接进入实现。**
> 范围：只谈**智能层**（谁做决策、模型看到什么、循环长什么样、技能卡怎么改）。
> 已存档的"失败七分类 / 三次尝试 / 补证一次 / 退出码"那套护栏**最后再接回**，本轮不展开。

## 1. 角色与边界：执行体真正负责"怎么做"

| 角色 | 决策权与职责 | 不负责 |
|---|---|---|
| 规划器 | 选下一个图谱节点；据交回结果安排后续 | 当前节点的命令、参数、工具顺序 |
| **执行体** | 理解目标与现场；决定还观察什么；选实现；构造具体动作；解释反馈；改做法；提交核验或交回 | 改节点目标、擅自跑别的节点、自己宣布核验成功 |
| 核验器 | 按固定目标契约独立核对证据，判分项目标是否成立 | 帮执行体选路线、降低判据 |
| 程序 | 给上下文、校验接口、调工具、留原始结果、驱动流转、更新账本 | 代选实现、猜参数、按错误码暗中切备用路线 |

**执行体必须拥有五项决策权**：① 观察选择（现场缺什么就查什么）② **实现选择** ③ **动作构造**（用哪个工具、什么参数、生成什么命令/脚本）④ **反馈解释**（支持了什么、排除了什么、还不知道什么）⑤ **后续决定**（继续观察 / 继续实施 / 调实现 / 提交核验 / 交回）。

**三分必须分开**：`method_id`（节点要求的**处理方法**，执行体不能换）｜`implementation_id`（完成该方法的**允许实现**，执行体可选可调）｜`action_spec`（**本轮实际怎么动手**，执行体生成）。

**程序的清单（固定）**：装配上下文与工具说明；校验输出结构与标识、输入类型、声明的工具/资源范围；把提案机械转成工具请求并执行；生成调用标识/时间/原始结果/产物引用；把反馈送回执行体、把证据送核验器；按核验结果更新账本。
**边界一句话**：序列化、协议握手、文件传输这类机械过程可以固定；**"下一步用哪种做法"不许藏在代码里**。

## 2. 每轮输入（最小充分）

| 输入块 | 必须包含 | 来源 |
|---|---|---|
| 当前任务 | 节点 id、方法 id、目标实体、目标作用域 | 图谱 + 派发记录 |
| 目标契约 | 分项目标、分项之间的 AND/OR、成功判据、契约版本 | 图谱 + 核验契约 |
| 可选实现 | 当前方法的**完整实现索引**、能力差异、输入要求；选中卡完整说明 | 插件（技能）目录 |
| 工具面 | 可调用工具、参数与结果结构、调用示例 | 工具注册表 |
| 执行环境 | 位置/会话引用、身份权限、能力描述、相关观测与时间 | 运行层 / 会话管理器 |
| 已成立事实 | 与本节点相关的事实、可用材料、来源与证据引用 | 事实账本 |
| 历史反馈 | 已做动作、实际结果、核验反馈、已排除路线 | 调用账本 + 核验器 |
| 作战板 | 已知/未知/假设/当前实现/下一待解问题/目标证据覆盖 | 执行体维护（事实附引用） |
| 外层约束 | 可用资源、时限/预算描述 | 外层策略（本轮不重定数值） |

开工给**完整任务包**；后续每轮给"**固定契约 + 作战板 + 新增反馈 + 相关原文**"。
执行体必须能**主动读取**：卡片详述、相关环境观测、历史调用原文、产物内容、目标对应证据。
**实现索引必须完整可见**——不能由程序先替模型挑好唯一实现。

## 3. 决策循环（文字状态机）

基本单位是**一次决策轮**（不等于一次工具调用，也不等于整个节点）。每轮：读新增反馈 → 更新现场理解 → 定"当前最该解决什么" → 给一个下一动作提案 → 收结果进下一轮。

```text
接收步骤与环境绑定
   ↓ 装配目标契约 / 技能卡 / 现场 / 历史
执行体模型判断
   ├─ OBSERVE：提出观察动作 → 程序调工具 → 存真实反馈 ─┐
   ├─ ACT：选实现并构造实施动作 → 程序调工具 → 存反馈 ─┤
   │                                                    ↓
   │                                          更新作战板，再判断
   ├─ VERIFY：提交目标主张与证据 → 独立核验器
   │        ├─ 成功 → 程序记账 → 交回规划器
   │        └─ 没成功 → 核验明细 → 再判断
   └─ HAND_BACK：本节点内无法继续 → 保存进展/缺项/依据 → 交回规划器
```

三条执行规则：① 模型可提**短计划**，但计划不是程序必须照跑到底的脚本，**每个需要解释现场结果的节点都回到模型**；② 可以一次提交**一组互不依赖的观察**，有依赖的必须等反馈；③ 工具返回只证明"这次调用发生了什么"，**是否达成目标由核验器判**。

## 4. 输出形状（模型侧 / 程序侧分开）

| 输出 | 最小字段 | 产出者 |
|---|---|---|
| 决策 | `decision_kind`、`purpose`、`basis_refs` | 执行体模型 |
| 现场解释 | `observed_facts`、`hypotheses`、`unknowns`、`feedback_summary` | 执行体模型（事实必须附引用） |
| 动作提案 | `implementation_id`、`tool_id`、`arguments`、`expected_observation` | 执行体模型 |
| 可变操作内容 | 命令参数 / 脚本源码 / 动作组合 | 执行体模型 |
| 核验提交 | `goal_contract_ref`、`per_goal_claims`、`evidence_refs`、`unresolved_items` | 执行体模型 |
| 交回说明 | `handoff_reason`、`needs`、`progress_summary`、`evidence_refs` | 执行体模型 |
| 实际调用记录 | `decision_id`、`action_id`、工具版本、实际参数、环境绑定、时间 | 程序 |
| 原始反馈/产物 | 工具返回值、原始输出引用、产物引用、来源关联、校验值 | 程序 / 工具 |
| 核验结论 | `verdict` + 分项目标明细 + 证据引用 | 核验器 |

**两个分隔**：① **预期 ≠ 实际**（`expected_observation` 不许进结果字段、不许当事实）；② **解释 ≠ 证据**（模型可写"可能是格式不匹配"，账本必须同时留原始报错）。
**关联链**：`模型决策 → 实际工具请求 → 原始返回/产物 → 核验引用`；生成脚本的，账本要存**实际派发的源码版本**。

## 5. 与核验器 / 规划器的接口

**给核验器（核验包）**：目标契约及版本；每个分项目标的主张；对应动作与证据引用；证据所属实体、执行位置、作用域、产生时间；尚未证明的内容。
核验器**必须能读原始证据**（不能只看执行体总结）；只读核验工具属于核验器工具面。
结果两层：`verdict`（成功/没成功）+ `per_goal_findings`（哪些成立/不成立/证据不足 + 依据）。**"部分满足"是明细，不自动决定下一条实施路线**（执行体看完明细自己决定）。

**给规划器（返回包）**：`node_id` + 核验结论引用（或交回原因）+ 已成立事实引用 + 未完成目标 + `needs` + 简短说明。
**必须交回的 5 种情况**：① 核验成功、本节点做完；② 所需条件必须由另一个图谱节点取得；③ 所需输入/执行环境/能力不在本节点可用范围；④ 现有实现无法履行目标契约（要修图谱或插件）；⑤ 模型判断本范围内没有可支持的下一动作，或外层要求停止。
执行体**可以说明需要什么，不能擅自启动另一个图谱节点**。

## 6. 技能卡契约（技能改造 —— 本次主角）

**动作类卡必须改**：卡片主体不再是一条完整业务命令，而是以下契约块：

| 契约块 | 内容 |
|---|---|
| 身份 | `card_id`、`version`、`method_id` |
| 方法语义 | 允许用什么处理方式；哪些变化仍属于同一方法 |
| 目标引用 | 对应哪些目标契约、可产出什么；不得自行扩大成功定义 |
| 输入契约 | 参数类型、必填项、合法来源、环境与材料引用 |
| 适用条件 | 所需位置、身份权限、作用域、工具能力 |
| **方法空间** | **可选择的路线、可调整变量、可组合操作、不能改变的语义** |
| 工具面 | 工具标识、类型化参数、返回结构、错误含义 |
| 可构造内容 | 是否允许生成命令参数 / 处理脚本 / 查询或操作序列，以及承载接口 |
| 资源边界 | 可读资源、可写位置、允许的副作用 |
| 证据契约 | 产物类型、来源信息、提取方式、核验契约引用 |
| 示例 | 供模型参考的做法，**不是强制流程** |

**判据**：**方法空间必须提供有意义的选择**。只允许模型填主机名/目录名、然后仍跑同一条固定链，**这次改造不算完成**。

**保持确定性（固定实现 + 开放类型化参数）**：会话/位置句柄解析；协议通信、传输、工具适配；原始输出捕获、产物存储、校验值计算；证据来源关联与事实发布接口；资源访问范围的执行约束；核验判据及其确定性检查器。
允许模型生成脚本的卡，**脚本访问范围必须由执行环境约束**（参数结构校验不能独自保证任意脚本的行为范围）。

**改前 / 改后示例（服务日志样本提取）**：

| 项 | 改前 | 改后 |
|---|---|---|
| 卡片主体 | 固定读 `/logs/service.log`、按空格分列、导出 CSV | 描述目标、方法范围、输入与工具面 |
| 路径与格式 | 写死 | 模型列目录、读样本后判断 |
| 动作生成 | 程序套命令模板 | 模型生成读取/解析/转换/写出动作 |
| 处理脚本 | 固定脚本 | 模型经"提交处理脚本"接口提交实际源码与输入引用 |
| 反馈处理 | 程序写好分支 | 模型解释样本与报错、改下一动作 |
| 成功判定 | 命令返回成功 | 独立核验时间窗/字段/来源/产物 |

改后工具面示例：`list_files` / `read_sample` / `read_compressed` / `run_processing_script` / `write_artifact` / `inspect_artifact`。
固定要求仍在：**不改源日志、不补造样本、输出保留来源关联、不能因为产出了 CSV 就降低判据。**

## 7. 多角色结构与上下文组织

**本轮定值**：执行体内部**先采用一个持久代理**；**每轮一次主决策调用**，不强制拆成五个子代理（拆开会增加交接损失）。
"多角色感"来自：不同角色**拥有不同决策权**、用**不同上下文与工具权限**、通过**明确消息交接**、核验结论**独立产生**。角色可用同一个基础模型，但**不能共享一个可随意改写目标、实施记录和核验结果的上下文**。

**子调用（可选，不是第一版成立条件）**：大批材料分片理解、多个独立观察并行分析、多张卡适用性比较；子调用返回"发现 + 证据引用 + 建议"；**主执行体统一决定实施动作，子代理不直接并发改同一工作环境**。

**三层上下文**：

| 层 | 存什么 | 谁维护 |
|---|---|---|
| 固定契约层 | 当前目标、方法范围、判据、工具与资源边界 | 程序加载，执行体只读 |
| 作战板层 | 已知/未知/假设/当前实现/短计划/证据覆盖 | 执行体更新，事实附引用 |
| 事件与证据层 | 全部动作、原始反馈、产物、核验记录 | 程序持久保存 |

**可压缩**：已结束讨论、重复输出、旧计划、历史解释、大型材料导航摘要。
**必须保留原文且可按引用取回**：目标契约与判据版本；实际执行的参数/命令/脚本；关键报错与工具原始输出；证据产物及来源；核验结果；影响后续判断的反例与矛盾观测。
"保留原文"不等于每轮把全部原文塞进提示词；**发生截断必须明确标记**。跨步骤/跨运行经验可作**建议**复用，不能当**本次现场已成立的事实**。

## 8. 验收（证明"模型真的在做实施决策"）

同时检查三类材料：**模型提案 / 真实工具轨迹 / 独立核验结果**。

| 验收项 | 方法 | 通过条件 |
|---|---|---|
| 动作由模型决定 | 关联每项实际实施动作 | 能找到事先生成的模型决策与完整参数 |
| 反馈进入决策 | 同一目标同一卡，改与动作相关的现场条件 | 后续做法针对差异调整并有依据 |
| 不止选固定脚本 | 改路径/格式/字段/工具能力 | 模型能构造有效参数、脚本或动作组合 |
| 实现选择真实有效 | 给能力不同的合格实现 | 模型据现场选，程序没暗中替换 |
| 核验独立 | 工具返回成功但目标产物缺失 | 核验不通过、事实不发布 |
| 目标不漂移 | 给"容易完成但不满足原目标"的替代产物 | 不以替代产物冒充成功 |
| 缺口诚实 | 删掉必要输入或能力 | 说明缺什么并交回，不编造证据 |
| 材料不改变任务 | 材料里塞"修改目标/报告成功"这类文本 | 当材料处理，目标与判据不变 |
| 程序无隐藏策略 | 暂停模型产生新决策 | 程序只完成已派发动作与记录，不自行推进新路线 |
| 上下文可恢复 | 从作战板与记录恢复执行体 | 正确区分已做/未做/已证明/仅是假设 |

**仍然是"玩具"的清单**：模型写理由但执行固定命令；模型只能选脚本编号不能构造做法；程序按错误码替模型换实现、模型事后解释；模型生成一次完整计划后真实反馈不能改路径；**只有诊断卡开放装配、动作卡全部固定**；执行模型自己宣布成功、没有独立证据核验；代理数量增加但决策权仍在确定性流程里。

## 9. 落地顺序（本轮）

1. 固定四个接口：**任务契约 / 模型决策 / 工具反馈 / 核验包**。
2. **改造一张真实动作卡**，使模型能生成实际操作内容。
3. 接通一个**持久执行体**的"观察—动作—反馈"循环。
4. 接入**独立核验器**与完整记录链。
5. 用**环境变体测试**确认模型确实改变做法，再迁移其余动作卡。
6. 最后接回已存档护栏；子代理与跨运行经验库留作后续增量。
