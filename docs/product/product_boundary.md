> 与 [最小数据契约](runtime_data_contract.md)（落盘工件）；本页只引用，不重复。

## 0. 交付什么（完整系统交付）

**交付一套自动化攻击路径验证 agent**：按输入的**攻击图**与**主机–IP 映射表**，
在**本地靶场**完成**攻击路径验证**。

前端与报告**不着急**：不算当前交付物、契约定稿缓行（阶段一验收契约里对应条目先行保留、缓行推进）。

## 1. 输入：只交两件

| # | 交什么 | 干什么用 |
| --- | --- | --- |
| 1 | **攻击图**：已经推理完成的版本 | 「打什么、按什么顺序打」的唯一依据 |
| 2 | **主机–IP 对账表**：主机 ↔ 地址的映射（一台主机多个地址也写在这一件里） | 解决多地址歧义；判定器认「打的是不是对的主机」靠它 |

除这两件之外，操作者不需要再交别的：在哪台机器上执行（Kali 地址）、用哪个模型，属于部署配置。
系统内部读取哪些文件、怎么体检，有单独契约：[运行输入契约](run_input_contract.md)。

## 2. 输出：两类

**① 事实类**（结论）
- 拿到的重要会话信息：哪条会话 / 什么身份 / 从哪个渠道来；
- 攻击步骤完成情况：每个节点一条结论（成功 / 没成功）+ 一句话理由。

**② 过程类**（过程台账，供后续界面与报告使用）
- 推理轨迹：按时间铺开——planner 给出的下一步、候选方法与选择理由、被拒的答案、
  每步判定所依据的理由。

## 3. 覆盖口径

- 分母 = 图里的全部节点，一个不缺；每个节点都必须有交代（成功 / 没成功 + 理由）。
- **不允许有「没提到」的节点**：没验证成的不会从报告里消失。
- 「节点成功」≠「整链可达」：逐节点结论与链路结论分开报，不合并。

## 4. 判定：成功 / 没成功

- 对外两级：**成功** 与 **没成功**。没成功内部再分两种：
  - **未成功**：验证过、站不住（能试的方法都试了）；
  - **待尝试**：这次没有结论（缺前提打不了，或证据不足判不了）。
- **怎么算成功，写在各技能卡上**（卡自带证据与判据）。例：LSASS 凭据转储——能输出凭据 = 成功；
  报错或空 = 没成功。判定按卡判据机械执行，**不需要人工介入**。
- 内部词不变：成功 `succeeded`（判定器 `pass`）；未成功 `failed`（`unsatisfied`）；
  待尝试 `blocked` / `uncertain`。真源：`src/runtime/vocabulary.py`、`src/runtime/checker.py`。

## 5. 执行与重试（"三次"语义）

- 一次完整 run 内，**同一个节点最多尝试 3 次**（第 1 次 + 最多 2 轮纠正）。
- 第 1 次失败后：把本轮**执行的命令 + 该节点的结构化数据**交给**审核 agent**，判断是命令/脚本问题
  还是参数问题，给出**修改意见**；意见回到**执行 agent**，带着意见重做命令。
- 3 次都没过：**停该节点**（含依赖它的下游），编排 agent 去找**剩余可行路径**。
- 预算归节点：跨执行器 / 技能 / 重规划共享，重启不清零；重做只从失败步骤接续。

## 6. 中断与恢复（2026-09-17 爷爷修正版）

四件事拆开：**恢复现场 / 审核重试 / 剪枝 / 重规划**；崩溃恢复、执行失败处理、业务判定三层不混。

- **前端掉线：不管**——不纳入恢复语义，运行照常（重连读的是同一次运行）。
- **进程重启：要管**——调用**派发前先落意图**（命令、目标、序号）；重启后先**核对在途调用**：
  还在跑→观察；已完成→取证；未执行→才允许重派；**不确定且有副作用→停发，记「结果未知」**。
- **Kali（执行端）**：**开工前前置检查**是否在线；运行中途**检测到 Kali 掉线 → 停止本次运行**
  （记原因），不自动重连、不自愈。
- **其他靶场虚拟机（靶机）**：不在本 agent 职责内——不判断、不重启、不参与恢复。
- 剪枝按条件传播（AND 阻断、OR 替代），独立分支继续；重规划限定在既定图与能力范围内。

## 7. 泛化边界（可测试）

- 能力范围可以只覆盖红日靶场所需要的能力；但**从输入数据处理到自动攻击全流程（含技能卡与适配器），
  不得针对红日写死**：不得出现具体 IP / 主机名 / 红日专属情形——数据怎么处理、流程怎么走，
  必须由输入驱动。
- 验收 = **变体测试**：更换地址映射、标识或合法参数并改变相关环境条件后，不改卡与代码也能
  正确调整执行或判定；配合代码审查（不能只靠替换 IP 证明没写死）。

## 8. 本地化边界

- 全本地：靶场 + Kali 在本机虚拟机；agent 项目本地；**agent 调用的模型也在本地**。
- 离线 CI 不依赖外部云；若 CI 含真实 agent 闭环，需有本地可用的推理服务。

## 9. 可核对性：报告的每个结论，你都能自己核对回去

- **翻得到**：每个动作有唯一调用编号（call），原始输出原样落盘——按编号就能翻到「当时到底跑出了什么」；
- **不冒充**：判定只看**这次调用**的输出，且要能同时对上**这次的目标**与**真实身份 / 效果**——上一次的残留输出、别的目标的回显、或「命令跑通了」都不算证据；
- **不涂改**：已落盘的东西只增不改；要更正就新增一条，历史永远翻得回去。

## 10. 非目标

- 不发现新攻击面：只验证输入图里的路径；
- 不打范围外的目标：只碰对账表覆盖的授权靶场地址；
- 模型不改图、不改判定：它只在边内做选择；
- 不做阶段二的自动渗透编排。
