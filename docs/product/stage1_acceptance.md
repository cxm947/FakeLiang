# 阶段一验收契约

> 来源：2026-09-16 中断恢复工程方案（run6）的「阶段一必过条件」表；2026-09-17 爷爷拍板：
> 前端与报告不着急（第 11、13 项缓行、不阻塞当前推进）。V0 入口见 [任务边界（V0）](product_boundary.md)。
> 口径：**首包通过 ≠ 阶段一完成**；阶段一以本表 15 项为必过条件，项目方直接验收并留档。
> 2026-09-18 爷爷口径修正：终验 = **打穿全部攻击节点**（不指定单条路径）；planner 自主选择每一步动作（顺序与方法）。

## 1. 验收表（15 项）

| # | 验收项 | 通过条件 | 必留证据 |
| --- | --- | --- | --- |
| 1 | 两件任务输入 | 从攻击图和主机–IP 对照表启动；不依赖隐藏的环境答案或额外手工剧本 | 原始输入、哈希、解析及参数来源记录 |
| 2 | 全图打穿 | 在约定基线环境中，输入攻击图的**全部攻击节点**均取得真实效果证据；planner 自主选择每一步动作 | 本次调用、目标身份、产物／效果、节点覆盖报告 |
| 3 | 全节点有交代 | 图中每个节点有结果或未执行原因；无无故消失的节点 | 节点清单及判定、调度状态、原因 |
| 4 | 真实性 | 展示数据来自本次后端和目标执行；断开执行端、改变输入后系统如实响应 | 实时事件、原始输出、故障测试记录 |
| 5 | 实现泛化 | 技能为通用方法＋检索键；目标信息可追到输入或观测，不能藏在技能卡、提示词、路由器或适配器中 | 必需技能覆盖表、代码审查、变体运行 |
| 6 | 泛化变体验证 | 更改地址映射、标识或合法参数，并改变相关环境条件后，无需改卡和代码，能够正确调整执行或判定 | 原版与变体输入、运行对照 |
| 7 | 反例 | 前提不成立、身份不匹配、旧证据／错误目标证据不能被判为成功 | 预期结果与实际结果、证据拒绝原因 |
| 8 | 失败处理 | 暂态问题可恢复；确定性失败提前停止；达到上限无第四次尝试；重启不刷新预算 | 完整尝试账本 |
| 9 | 剪枝与重规划 | AND 阻断、OR 替代、独立分支继续、无路可走结束均符合规则 | 分支事件及最终报告 |
| 10 | 崩溃恢复 | 在派发前、派发后结果未确认、证据已落盘而状态未提交等位置中断，恢复后无漏记、无盲目重复 | 故障注入位置、恢复事件、目标效果核对 |
| 11 | 真实网页版（缓行） | 展示决策摘要、步骤、状态、证据；刷新和重连后连续一致；能与本次已建立会话交互 | 浏览器验收记录及对应调用 ID |
| 12 | 会话真实性 | 项目方现场执行带随机内容的交互并核对主机／身份；会话失效如实显示 | 命令、实时响应、会话绑定信息 |
| 13 | 报告与离线复判（缓行） | 页面、报告、事件账本相互一致；固定证据及判定器版本可复判得到一致结果 | 报告、证据目录、复判结果 |
| 14 | 版本绑定 | 每份验收结果能追到精确代码、输入、技能、判定器、模型配置及环境版本 | 运行清单 |
| 15 | 本地可复现 | 本地干净工作区及约定 VM 基线可复现；离线 CI 不依赖外部云；核心用例不得以跳过计为通过 | CI 结果、环境清单、项目方验收记录 |

## 2. 必达范围：全图打穿

- 必达 = 输入攻击图的**全部攻击节点**（不指定单条路径）：每个攻击节点都要取得**真实效果证据**；
  planner 自主选择每一步的动作（顺序、方法选择、失败替换），验收按「全部攻击节点打穿」判定。
- 「真实复现」必须有正向验收：**不能仅凭一份正确记录了全图失败的报告**，就认定复现完成；
  同时也不要求反例场景与所有可选分支都成功。
- 首包先跑一条最小纵向链路做演示（代表性真实路径）；阶段一终验 = 全部攻击节点打穿 + 上表全部条件 +
  约定环境的必需技能。

## 3. 口径与边界

- 测试用例的「通过」与节点的业务判定分开：例——反例正确得到「没成功」，该验收用例应当**通过**。
- 泛化验收限定在既定技能范围内，不扩展成「适配所有环境」；变体测试与代码审查配合使用，
  不能只靠替换 IP 证明流程没有写死。
- 执行端（Kali）在线是**启动前置条件**（开工前检查）；运行中检测到掉线即**停止本次运行**，
  不自动重连；靶场其他虚拟机（靶机）不在本 agent 职责内（2026-09-17 爷爷口径）。
- 第 11、13 项（前端 / 报告）缓行说明见本页头部：条款保留，推进时再定契约。
