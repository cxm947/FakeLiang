## 1. 全貌

```
① 输入：攻击图 + 资产表 + 运行上下文
        │
        ▼
② 流程驱动算出"这一轮的局面"（看板）：谁没结案、谁已经被验证成功、谁现在可以打
        │
        ▼
③ Planner（模型）看这页看板，只说三句话之一：
        「打这个节点」 / 「结束了」 / 「我不说了（暂停）」
        │
        ▼
④ 流程驱动校验这句话 → 通过就派发；不通过就把**同一页看板 + 拒绝理由**回喂重问
        │
        ▼
⑤ Executor 接管这个节点：自己选做法、自己动手、按反馈改，最多三次真实尝试（三次之间不打扰 Planner）
        │
        ▼
⑥ Verifier 按这个节点的判据看证据 → **只给 Planner 两个字：成功 / 没成功**
        │
        ▼
⑦ 流程驱动记账（方法成功 → 照图推出哪些事实可用）→ 回到 ②，直到没有可以打的节点
        │
        ▼
⑧ 收尾：按"必做方法是否全部成功"给运行结论
```

**两条基本设定（甲方口径）**：

- **按攻击图的逻辑走，不会"缺东西"**：一个节点的上游事实没成立，它就不是候选——**不存在"等待"这种状态**。
- **事实不在这里判定**：这一层只有"某个方法成功/没成功"；某条事实成立，是**照图推**出来的
  （"产出它的那个方法被验证成功了"）。

## 2. 四个角色

| 角色 | 业务职责 | 看什么 | 产什么 | **绝不做什么** |
|---|---|---|---|---|
| **流程驱动**（程序） | 算局面、校验、派发、记账、收尾 | 图 + 台账 + 三个角色的产出 | 看板、事件记录、运行结论 | 不替模型挑节点；不判事实；不把"没做完"写成"做完了" |
| **Planner**（模型） | **在合法候选里挑下一个节点**；或说"结束了"；或说"我不说了" | §6 看板 | 一个节点编号 + 一句理由，或一个结束请求 | 不写命令、不改图、不改验收标准、不宣布成功 |
| **Executor**（执行器） | 接管被选中的节点：选做法、动手、按反馈改，最多三次真实尝试 | 节点的要求 + 自己的进展 | 实际执行记录、观察、给验证器的材料 | 不换节点、不改目标、不替验证器判成功 |
| **Verifier**（验证器） | 按**该节点的判据**看证据，判这个节点成不成立 | 原始证据 + 判据 | **给 Planner 只有：成功 / 没成功**；细节留给自己和执行器 | 不挑节点、不下命令、不写事实 |

## 3. 各部分的接口（输入 / 输出）

### 3.1 流程驱动 → Planner：一页看板

| | 内容 |
|---|---|
| **输入** | 图版本、必做方法集合、每个方法的状态（未结案/执行中/已结案 + 成功或没成功）、**当前可以打的节点**、上一步（选择与实际） |
| **输出** | 一页看板（字段见 §6） |
| **约束** | 只呈现"方法成功/没成功"；**不判事实**；可以打的节点 = 图上上游事实已由某个方法成功产出、且自己还没结案 |
| **失败时** | 图或台账不完整 → 不生成看板，报"缺什么" |

### 3.2 Planner → 流程驱动：一句话决定

| | 内容 |
|---|---|
| **输入** | 看板（§6） |
| **输出** | 三选一：`打这个节点`（编号 + 一句理由）／`结束了`（一句理由）／`我不说了` |
| **约束** | 编号必须来自看板的"可以打的节点"；理由只给人看，不影响判定 |
| **失败时** | 编号非法 → 拒绝并回喂理由；连续给不出 → 暂停运行 |

### 3.3 流程驱动 → Executor：一个节点任务

| | 内容 |
|---|---|
| **输入** | 要验证的方法节点（编号 + 它要证明的事实 + 该事实的判据）；可用的执行位置与会话；已有材料；**剩余尝试次数**；整轮剩余预算 |
| **输出** | 一条"我接下这个节点了"的接受记录（进入节点执行周期） |
| **约束** | 同一节点同一时刻只能被一个执行周期占用；**三次尝试之间不回到 Planner** |
| **失败时** | 接不下（例如现实里发现前提并不成立）→ 立即回报并附原因 |

### 3.4 Executor → Verifier：一次执行的结果

| | 内容 |
|---|---|
| **输入** | 节点任务 + 自己的进展（试过什么、用过什么位置与身份） |
| **输出** | ①实际发出与收回的记录（命令、返回、原始输出、耗时、位置、身份）；②这次尝试的观察；③执行器认为"这条证据支持什么"的说明（**只是说明**）；④这是第几次尝试 |
| **约束** | 原始记录**不许改**；执行器的说明与原始记录**分开存** |
| **失败时** | 结果不明（发了但不知结果）→ 标"待核对"，**不能当失败重试** |

### 3.5 Verifier → 流程驱动：一个节点的结论

| | 内容 |
|---|---|
| **输入** | 该节点的判据 + Executor 给的全部材料 |
| **输出** | 一个结论：`成功` / `没成功`；附判据与证据的对应关系（留给自己与执行器）；证据不足时附"还缺什么" |
| **约束** | 按节点类型判（§7.3）；**不许用"命令跑通了"代替"效果成立"**；证据不足**不能反过来说事实为假** |
| **失败时** | 证据不足 → 记"没成功（证据不足）"，并把"缺什么"给 Executor 让它接着补 |

### 3.6 流程驱动 → Planner（下一轮）：只剩两个字的结论

| | 内容 |
|---|---|
| **输入** | 上一个节点的验证结论 |
| **输出** | 写进看板的方法状态：`成功` / `没成功`（**没有证据细节、没有原因长文**） |
| **约束** | 细节留在执行器/验证器那边；Planner 需要时按需再读 |
| **失败时** | 结论本身不明（如在途未核对）→ 方法保持"未结案" |

### 3.7 流程驱动 → 记录：账

| | 内容 |
|---|---|
| **输入** | 决策记录、执行事件、验证结论 |
| **输出** | **方法轴**（每个指定方法做过什么、结没结案、被验证成功还是没成功）、**事实可用性**（照图推导）、**三类计数**、执行事件流 |
| **约束** | 方法轴**不借别人的成功**；**事实不在这里判定**——某条事实可用 ⟺ **至少一个产出它的方法已被验证成功**；计数按方法数统计（§7.4） |
| **失败时** | 提交中断 → 恢复后**不许重复统计**，也不许产生"半次提交" |

### 3.8 收尾接口：完成请求

| | 内容 |
|---|---|
| **输入** | Planner 的"结束了" + 当前快照 |
| **输出** | `接受` / `拒绝`；拒绝时附**未完成项**；接受时附**运行结论** |
| **约束** | **只判定、不动作**：拒绝时**不许派发任何节点**，也不许改变执行次数 |
| **失败时** | 见 §9 的四种裁定 |

## 4. 一次运行的完整流程

| 步 | 谁 | 做什么 | 产物 |
|---|---|---|---|
| 1 | 流程驱动 | 冻结本次运行的图版本与**必做方法集合** | 运行契约 |
| 2 | 流程驱动 | 算**可以打的节点**（自己没结案、没被占用、上游事实已由某个成功方法产出） | 候选清单 |
| 3 | 流程驱动 | 组装看板 | 一页看板 |
| 4 | Planner | 选一个节点（或请求结束） | 选择 + 理由 |
| 5 | 流程驱动 | 校验；通过→派发；不通过→同一页看板+理由回喂重问（有次数上限） | 接受/拒绝记录 |
| 6 | Executor | 接管节点，自己循环，最多三次真实尝试 | 执行事件、观察 |
| 7 | Verifier | 判这个节点 | 成功 / 没成功 |
| 8 | 流程驱动 | 记账（方法轴 + 照图推事实可用性 + 计数） | 更新后的看板 |
| 9 | 流程驱动 | 回到第 2 步；没有可以打的节点就收尾 | 运行结论 |

## 5. Planner 的三句话（与什么算非法）

### 5.1 「打这个节点」

流程驱动检查三件事，全过才派发：

1. **在图上**（编号唯一对应一个节点）；
2. **没结案、没被占用**（不在执行中/核对中）；
3. **上游事实已经有主**（它依赖的那几条事实，各自至少有一个产出方法已被验证成功）。

不通过就拒绝，并把**人话理由**回喂，例如：

- "节点 2 现在不能执行：它依赖的 `execCode(pc1,system)` 还没有任何一个产出方法被验证成功。请另选可执行的节点。"
- "节点 12 已经结案（结果：成功）。请另选。"

（**没有"等待"这种说法**：依赖没成立的节点，本来就不在候选里。）

### 5.2 「结束了」

流程驱动**只判定、不动作**（§9）。

### 5.3 「我不说了（暂停）」

模型不可用、或连续给不出合法答案达到上限 → 暂停运行并写明原因，**绝不回退到固定顺序**。

## 6. 看板（Planner 每轮看到的东西）

| 字段 | 含义 | 红日7 实例 |
|---|---|---|
| 图版本 | 本次运行冻结的图 | 红日7 v2 |
| 必做方法集合 | 见 §7.1 | 图上的 AND 方法节点 |
| 方法清单 | 每个方法的状态（见下） | — |
| **可以打的节点** | 当前**全部**合法候选（不是只有当前分支） | 开局是 `14、30` |
| **分支提示** | **只表达偏好** | `{最近实际跑了:7, 偏好:2,44,48, 理由:"刚拿到 pc1 的执行能力"}` |
| 覆盖计数 | 必做总数 / 已尝试 / 已结案 / 已确认成功 | `14 / 10 / 10 / 10` |
| 上一步 | 最近一次**选择**（谁、接受还是被拒）与最近一次**实际执行**（谁、结果） | — |

方法清单里每个方法带：

| 字段 | 含义 |
|---|---|
| 节点编号 | — |
| 处理状态 | `未结案 / 执行中 / 核对中 / 已结案` |
| 终局 | `成功 / 失败 / 超时 / 空`（§8） |
| 已尝试次数 | 0~3 |
| 一句话说明 | 给 Planner 看的简短说明（**不写证据细节**） |

**两条纪律**：
1. "可以打的节点"必须包含**所有**合法候选；分支提示里的偏好**必须是它的子集**。
2. 流程驱动**只校验"在不在候选里"，不校验"在不在偏好里"**——选别的合法分支**不算错、不扣次数**。

## 7. 事实怎么算、方法怎么记账

### 7.1 必做方法集合（甲方口径）

> **必做 = 图上的 AND 方法节点。**
> **每个方法必须有自己的"执行 + 证据"**；A 方法成功了，**不能替 B 方法结案**。

### 7.2 事实不在这里判定

> 这一层**不判事实**。某条事实"可以用"，只有一个来源：**图里产出它的那个方法被验证成功了**。
> 如果一条事实有多个产出方法，**只要其中一个成功，这条事实就可以被下游使用**；其他产出方法**仍要各自验证**。

所以看板上不需要"事实清单"（更不需要"缺什么、谁来补"）：**能不能打，照图一推就知道**。

### 7.3 各类型"事实"的判据（这是**验证器**的判据，不是流程驱动的）

| 事实种类 | 判据（怎么算成立） |
|---|---|
| 执行类（如 `execCode(主机,权限)`） | **存在这个权限的可用会话**（能证明"在这台机上、以这个身份、真的执行了"） |
| 可达类（如 `netAccess(主机,端口)`） | **从指定位置验证了连通性** |
| 凭据类（如拿到某账号材料） | **拿到可用材料**（不是"看起来像凭据的文件"） |
| 防御设置类（如关掉某主机的防御设置） | **状态真的变了**（不是"命令被接受"） |

### 7.4 三类计数（不许混用）

| 计数 | 定义 |
|---|---|
| 已尝试 | 真实派发过的方法数 |
| 已结案 | 已经有终局结果的方法数 |
| 已确认成功 | 终局 = 成功的方法数 |

另单列 **"证据足以判定目标"** 的方法数（不是"足以解释为什么阻塞"）。

## 8. 方法终局与三次尝试

### 8.1 三种终局

| 终局 | 次数 | 成立条件 |
|---|---|---|
| `成功` | 1~3 | 真实执行过，且验证器按判据确认通过 |
| `失败` | **恰好 3** | 三次尝试都已核对结束、都没成功，证据支持"本次受限验证未成功" |
| `超时` | 0~3 | 已进入执行周期、预算耗尽，且**所有派发与在途都已核对**，仍未完成 |

**从未派发过的方法没有终局**（它就是"没打过"）；收尾时按 §9 计入"没打完就停了"。
`失败` ≠ 事实为假；执行中 / 核对中都不是终局。

### 8.2 三次尝试怎么数

| 情形 | 算不算 |
|---|---|
| 一个动作真正越过"派发边界"被执行端接纳 | **算** |
| 动作开始后立即报错或没产生预期效果 | **算** |
| 同一次动作里的多次观察、等待、验证 | 不算 |
| Planner / Executor 的模型调用 | 不算 |
| 解析失败、参数准备、没派发的条件检查 | 不算 |
| 能证明"动作没开始"的派发失败 | 不算 |
| 回执丢了、到底发没发不清楚 | **先核对**（期间不许发下一次） |
| 重复收到同一次动作的回执 | 不算（按尝试标识去重） |

**成功立刻返回，不补足三次；失败不能少于三次就返回；三次之间不打扰 Planner。**

## 9. 结束与收尾

### 9.1 收到"结束了"时的四种裁定

| 当前局面 | 裁定 | 记什么 |
|---|---|---|
| 必做方法全部成功、没有在途 | **接受** | 运行结论 = **全部打通** |
| 必做方法全部结案，但里面有失败/超时 | **接受结束** | 运行结论 = **都打过，但有些没打通**（并列出是哪些） |
| 还有可以打的必做方法 | **拒绝** | 列出未完成项；**执行次数不变**；把看板连理由回喂重问 |
| 有执行中 / 派发不明 / 待提交 | **拒绝最终结束** | 继续核对，不派发替代节点 |

### 9.2 三种运行结论

| 结论 | 判定 |
|---|---|
| **全部打通** | 必做方法**全部成功** |
| **都打过，但有些没打通** | 必做方法**全部结案**，且存在非成功 |
| **没打完就停了** | 其它情形（还有未结案的方法） |

## 10. 离线验收用例（不用模型也能跑）

| # | 注入什么 | 期望 |
|---|---|---|
| 1 | 选 A，派发前发现实际是 B | **拒绝派发**；保留差异；次数都不增加 |
| 2 | 选 A，真跑完才发现跑的是 B | 不覆盖选择；单独记 B 并核对归属；**不给 A 记次数或成功**；暂停常规调度 |
| 3 | 建议 A，但 B 也合法，模型选了 B | **接受 B**；不记"非法选择" |
| 4 | 当前分支没得打，别的分支有 | **别的分支完整出现在候选里** |
| 5 | 上游事实还没有任何产出方法成功 | 依赖它的节点**不在候选里**；被选中时拒绝理由点名该事实 |
| 6 | A 成功了、B 是另一个必做方法 | **B 仍未完成**；B 的前提满足时仍可派发 |
| 7 | 必做全部成功，但还有可选方法没跑 | **接受结束**（不强迫跑可选） |
| 8 | 必做全部结案、含三次失败 | 接受结束，报告"不是全部成功" |
| 9 | 还有可推进的必做项，收到"结束" | **拒绝**，列出未完成项；**执行次数不变** |
| 10 | 三次失败 | 记 `失败`；**不存在第四次派发** |
| 11 | 一次后预算耗尽且已核对 | 记 `超时`，停止本轮 |
| 12 | 预算耗尽后核对发现其实成功了 | **记成功**，不记超时 |
| 13 | 回执丢失/重复 | 同一个真实动作**只计一次** |

接真模型后的硬指标：**全候选可见率 100%**；候选外派发 / 静默替代 / 身份偏差 / 节点内插 Planner / 错误计数 / 未核对终局 / 部分提交 **全为 0**。

## 11. 落地顺序

| 步 | 做什么 | 验收 |
|---|---|---|
| 1 | **把账记准**：选择与实际分开记；方法轴补终局与次数；执行事件带"选了谁/实际是谁" | 用例 1、2 |
| 2 | **把候选算准**：候选 = 上游事实已有主 + 自己未结案；照图推，不判事实、不算等待 | 用例 4、5、6 |
| 3 | **把话说清**：校验只查候选；完成请求改成只判定不动作 | 用例 3、7、8、9 |
| 4 | **节点内循环**：三次尝试、成功即返回、期间不插 Planner、核对规则 | 用例 10、11、12、13 |
