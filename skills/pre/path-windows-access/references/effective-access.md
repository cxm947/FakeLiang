# 有效写权限证据

## 选择方法

优先使用检查环境中已有的有效访问查询能力。若已有 Sysinternals AccessChk，
可按其版本帮助查询指定身份和对象。示意用法：

    accesschk.exe -nobanner -v "DOMAIN\user" "C:\example\file.txt"

身份与路径必须来自当前上下文；未部署的工具不能当作已经可用。
首次使用若出现交互许可提示，返回的是工具前置问题，不是对象权限结果。
本技能不安装工具、不更改系统配置。

## 需要区分的权限

- 文件：关注有效 FILE_WRITE_DATA/相应写入权限；仅能改属性不等于可写内容。
- 目录：关注有效 FILE_ADD_FILE 等对应创建内容的权限；不实际创建文件。
- 仅有追加权限、部分写入能力而不能对应本图的“可写”含义时，说明证据并保持未知。
- UNC 路径还可能受到共享权限约束，单独的 NTFS Allow 不能证明经该路径可写。
- 账号级有效访问与当前过滤令牌可能不同，不能忽略身份、组与令牌限制。

## 不足的证据

Owner、只读属性、管理员组身份、某一条 Allow ACE，都不能独立证明有效写权限。
需要同时考虑拒绝项、继承、组成员及实际对象类型；无法确定则返回未知，
不要临时实现一个只看 ACL 字符串的权限算法。

工具返回空白或认证/查询失败不是“没有写权限”。只有可靠的有效权限查询才支持阴性结论。

工具参数参考：[Microsoft AccessChk](https://learn.microsoft.com/en-us/sysinternals/downloads/accesschk)。
