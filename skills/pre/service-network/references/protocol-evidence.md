# 协议证据判读

服务识别不足或存在包装协议时使用本资料。地址、端口始终来自当前 LEAF。

| 声明服务 | 可用的正向证据 | 不足的证据 |
|---|---|---|
| Redis | PING 的 PONG 响应或明确 Redis 协议的认证拒绝 | 6379 开放 |
| HTTP | 有效 HTTP 状态行/响应头 | 80/443 开放 |
| SSH | SSH 协议标识或握手响应 | 单凭 22 端口名称 |
| SMB | SMB 协议协商响应 | 445 开放 |
| SCM | 服务管理器接口实际回应 | SMB 成功，不代表 SCM 已验证 |

## 最小协议请求示例

    timeout 8s redis-cli -h 192.0.2.10 -p 6379 PING
    curl --max-time 8 --head http://192.0.2.10:8080/

执行面上不一定装了上例的客户端。**按"可用客户端 → 解释器 → 有限识别"的顺序退让**：没有 `curl`/`nmap` 时，用执行面已有的解释器发一次同样的只读请求（Python 3 示例）：

    python3 -c "import urllib.request;d=urllib.request.urlopen('http://192.0.2.10:8080/',timeout=8).read();print(d[:600].decode('gbk','replace'))"

正文按**目标实际编码**解码再找标识（本部署实测：该产品的首页是 GBK，标题里就带产品名；按 UTF-8 硬解会看到乱码，等于看不到标识）。**只取有限首页/标题或产品专属响应，不扩大目标范围，不做利用。**

使用实际参数替换示例。HTTP 401/403/405 仍可证明 HTTP 在响应，不要求业务请求成功。
声明是某个具体产品时，通用 HTTP 响应还不能证明产品身份。
此时读取有限的首页正文、标题或产品专属响应，并保留匹配声明产品的标识；仅 `200 text/html` 必须判未知。
TLS 证书错误不等于服务不存在。

Windows 已有身份环境检查远程 SMB 时，可通过标准 Windows SMB 客户端只读访问目标 IPC$，
或打开目标已知的命名管道并保留实际目标及传输端点证据。原生客户端若不能指定输入要求的端口，应换支持该端点的客户端。接口/共享不可用不等于 SMB 不存在。
优先使用已有协议库/系统客户端，不临场拼凑未经验证的 SMB 协商字节。

## 结果边界

- 带问号的服务名、推测名称和未识别项不是确定证据。
- 连接拒绝支持该地址端口当前不提供服务；超时/过滤不能区分服务缺失与访问受阻。
- 顺带显示的版本可以保留在证据中，但不用于本次条件判断。
- 截断或外层超时应说明缺少什么，不把空输出解释为服务不存在。
