# 网络服务存在检查

## 适用场景

需要目标地址、预期服务/接口、已知传输方式及端口约束。
本方法验证远程协议响应；若任务仅要求本地进程或服务状态，选择本地查询方法。
只检查声明服务是否存在并响应，不比较版本、不检查服务账号权限。

## 参数

- 输入：本页「适用场景」声明的目标、地址/端口、平台与执行面；由运行层给出，**不得杜撰**
- 交付：evidence
- 执行位置：position
- 可用工具：cmd、code（脚本类步骤用 code + python3，命令类步骤用 cmd）


## 步骤

**进入条件（先看这条）**：本卡需要「适用场景」里声明的输入（目标、地址/端口、平台、执行面）已经由运行层给出；缺输入就先说明缺什么，不要换方法硬凑，也不要去起监听或新建会话。

**一条一个动作块**：一次答复只给一个请求；不拼长行、不发数组、不把多步塞进一条命令。

**输出纪律**：`content` 只放一条最小命令；不要把本卡说明、示例全文、协议报文或字节数组复制进去。需要脚本时正文也要短。

```text
{"tool":"run_script","target":"session","arguments":{"interpreter":"python3","body":"<本卡方法里那段脚本>"}}
```

**`tool=session` 只用于会话自己的控制台命令，不是系统 shell。** 绑定 Linux 会话时，协议响应必须用
`code`（python3）或 `cmd`（sh/curl），`via=session`；第一次用错工具得到 `Unknown command` 时，换工具形状，
不要原样重发。

Linux 会话的 Python 输出按 ASCII 编码，直接 `print()` 中文页面会报 `UnicodeEncodeError`。取正文用：

```text
{"tool":"run_command","target":"session","arguments":{"interpreter":"sh","command":"python3 -c \"import urllib.request,sys;d=urllib.request.urlopen('http://<target>:<port>/',timeout=8).read();sys.stdout.buffer.write(d[:600]);sys.stdout.write('\\n')\""}}
```


1. 确定一个目标和声明端口，确认 TCP/UDP 类型，不凭端口号推测服务。
2. **本条是能力义务，不是工具清单**：必须完成"取得一次只读协议响应"这件事。首选实现是执行面声明的只读客户端（本部署源主机上 `curl`/`nmap` 均不存在）；首选不可用**只终止这条实现路径**，继续走清单允许的等价路径（执行面已有的解释器发同一次只读请求 → 有限服务识别）。**只有所有允许路径都不可用或执行失败、或达到明确预算，才以具体原因记未知**；不因缺少某个客户端就跳到"未知"。等价路径要能产出判断所需的那部分证据——拿到了内容但丢了判断所需信息，不算等价成功。
3. 收集端口状态及协议响应，区分外层协议和声明的具体服务。
4. 根据 [协议证据说明](references/protocol-evidence.md) 判断证据是否充分。

以下示例检查一个 TCP 端口，替换当前目标和端口：

    nmap -n -Pn -sT -sV --version-light -p 6379 --max-retries 1 --host-timeout 20s 192.0.2.10

-Pn 避免因主机发现失败而跳过端口；-sV 尝试识别服务，-p 限定单端口。
UDP 使用对应探测模式，环境权限不足记未知。总耗时应在执行通道预算以内。
不增加全端口、漏洞扫描或默认脚本集合。

**声明的是 `smb` 时，优先用一条有界客户端命令，不要手写 SMB 协商字节：**

- Windows 执行面：`net view \\<目标主机>`。返回共享列表、空列表或明确的访问拒绝，都说明 SMB 有响应；命令不存在、超时、找不到主机记未知。
- Linux 执行面：`smbclient -L //<目标主机> -N`（无匿名访问时加 `-U ''`）。同样只发一次。
- 以上都不可用：记未知（缺少 SMB 客户端），不要临场拼 `bytes.fromhex(...)`、长十六进制串或完整 SMB 报文。

回执里 `stdout` 是执行面回显原文、`return_code` 是命令终态；`cmd`/`code` 落在已登记会话上时字段是 `output` 与 `operation_confirmed`。`timed_out=true` 或 `effect_known=false` 表示预算内没有拿到可确认的结果，那是**结果未知**，不是通道失效，也不是命题不成立。

本步判 `通过` 需要出现上面判读表里那一行要求的证据；出现明确反证判 `不通过`；工具缺失、参数错误、输出截断、通道中断一律 `未知`。

**停止边界**：本卡一次调用只做本页方法里的一次检查；不由本卡重试、追加动作、换目标或扩大范围；首选实现不可用时走本页声明的等价路径，路径耗尽就记未知并写明具体原因。


## 完成依据

| 证据 | 结论 |
|---|---|
| 声明端口返回匹配的协议响应 | 通过 |
| 完整检查明确端口关闭，或明确实际服务与声明不符 | 不通过 |
| filtered、open/filtered、unknown、tcpwrapped 或识别不足 | 未知 |
| 客户端缺失、参数错误、执行中断 | 未知 |

**声明是具体产品时**（例如声明 `service=<产品名>`）：通用 HTTP 响应**不足以**证明产品身份，必须再读一次**有限的首页正文或标题**并命中该产品的标识；**只看到通用 `200 text/html` 一律判未知**。执行面没有 `curl`/`nmap` 时改用执行面已有的解释器（Python 3 示例）取有限正文，并**按目标实际编码解码**——先按 UTF-8 解，出现替换字符或乱码时再按目标声明的编码解；编码不确定就保留未知，不能把乱码当成“未命中”：

    python3 -c "import urllib.request;d=urllib.request.urlopen('http://<target>:<port>/',timeout=8).read();print(d[:600].decode('utf-8','replace'))"

**先把命题写准**：本卡要证的是"**响应中呈现了该产品标识**"，还是"**当前服务确为该产品**"？前者读到一个产品特异标识即可；后者还需要排除代理页/缓存页/仿制页。标题里的产品名对前者足够、对后者只是线索。

**未发现标识 = 身份尚未证实**（不是"环境不可用"，也不是"身份不成立"）：只有**取得可合理解释的文本之后**，才允许据标识匹配或缺失作文本层判断；**解码存在未解决疑点时，不得把"未匹配"当作反证**（记录所用编码、依据与异常）。只有出现明确反证，或完成具备排他性的必要条件检查，才判身份不通过。**多项弱证据不能靠数量累加成身份通过。**

**不许反复换编码直到碰巧命中再用命中反证解码正确**；已知的 GBK 是"有依据的兼容路径"，不是"该产品一切版本都用 GBK"。边界分层：分块传输=消息重组、压缩=内容还原（先确认已正确处理，客户端已处理的不重复处理）、字符编码=文本；二进制响应改用对应格式判据；截断/损坏/无法解码时记录**采集或解释限制**，有限读取不能默认标识所在位置已被覆盖。

端口开放或默认端口名称不能独立证明服务类型。
未知时选择更具体的只读协议握手，不扩大目标范围，不执行利用。
认证拒绝可能证明协议存在，但不能证明更深层组件存在。

## 失败条件

- 检查工具不存在、参数错误、输出被截断或执行通道中断 → 未知；这些都不是命题不成立的反证。
- 本卡一次调用只做本页方法里的一次检查；不由本卡重试、追加动作、换目标或扩大范围；首选实现不可用时走本页声明的等价路径，路径耗尽就记未知并写明具体原因。

## 什么时候做什么（先判情形，再按顺序做；别让执行者猜）

| 先判这个 | 做什么（按顺序） | 什么时候算完 | 什么时候停 |
|---|---|---|---|
| 执行面有清单示例里的客户端 | 发一次最小只读请求 | 拿到协议响应 | 客户端报"命令不存在" → 换下一条 |
| 首选客户端不在（**本部署实测：`curl`、`nmap` 都没有**） | ① `wget -q -O - <url>`（本部署实测可用）；② 仍无 → **单行** `python3 -c '…'` | 拿到响应正文 | ① ② 都不可用/都失败 → 记**未知**并写明具体原因（不是"环境不可用"） |
| 声明的是**具体产品** | 在上一条基础上再读一次**有限首页/标题**，并**按目标实际编码解码** | 命中产品标识 → 身份**通过** | 读到正文但没有标识 → **未知**（身份尚未证实） |
| 要在会话通道上发一段脚本 | 用 `cmd` + **单行** `python3 -c '…'`；**不要用 `code` 工具**（会话通道按请求里的解释器执行，选错解释器会变成 shell 语法错误） | 回执里有正文 | 出现 `Syntax error`/`not found` → 换成 `cmd` 单行形式重发 |

**每一步只做上表允许的那件事**；换客户端属于"同一件事的等价路径"，不是换目标、更不是扩大范围。

## 结果分类（先记录观测事件，再对命题判定）

| 情况 | 判 | 边界 |
|---|---|---|
| 声明的客户端不存在 | **当前工具路径不可用；事实判定尚未完成** | 必须继续允许的等价路径；路径耗尽后待证事实才记未知。若命题本身就是"该客户端存在"，则不通过 |
| 有限正文已读到、但没有产品标识 | **未知**（身份尚未证实） | 只有当标识是必要条件、解码与读取范围确实足以保证应当看到它时，缺失才支持不通过 |
| 已读到标识、但未确认更深层组件 | **身份通过；深层组件未知** | 标识满足身份门槛才算通过；标识只是弱线索时身份仍是未知 |

**依赖该命题的后续步骤：只有"通过"才放行；"不通过"与"未知"都必须阻断依赖**（但不阻断与该命题无关的步骤，也不阻断清单允许的补证路径）。
