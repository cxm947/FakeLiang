# nmap —— 端口可达性与服务标识

## 这个工具能回答什么

两件不同的事，别混成一件：

1. **有没有一条能建立的 TCP 连接**：从一个指定位置到一个指定目标端口（`pre.nmap_tcp_probe`）。
2. **一个已经可达的端口上，服务自称是什么产品、什么版本**（`pre.service_version` 的标识路由）。

`open` 只说「有东西在听」，不说「是什么」；服务标识也不说「有没有漏洞」。两条都是**观测**，不是结论。

## 调用形状

可达性（无特权、不做主机发现与反解、结果以 XML 落到 stdout）：

```sh
nmap --unprivileged -Pn -n -sT --reason -p <port> -oX - <target_host>
```

标识读取（目标端口已确认可达时）：

```sh
nmap -Pn -n -sT -sV --version-light --reason -p <port> -oX - <target_host>
```

为什么是这几个开关：

- `--unprivileged -sT`：合起来保证网络行为就是一次普通 `connect()`。控制端的外部命令要经转发入口
  发出时，只有普通 TCP 调用会被接管 —— 这条对本仓的可达性卡是硬要求。
- `-Pn -n`：关掉主机发现与反向解析，去掉两个额外的不确定性来源。
- `-oX -`：XML 到 stdout，交给程序解析，不靠模型读屏。

## 输出怎么读

- 端口行的 `state` 有三种：`open` / `closed` / `filtered`。`closed` 也是有效结论（可达但无监听），
  不要当成失败；`filtered` 是「没收到明确回应」。
- `--reason` 给出判定依据（`syn-ack` / `conn-refused` / `no-response`），它是证据的一部分，单看
  `state` 会丢掉它。
- `-sV` 的产品与版本来自探测回包，服务可以伪装或改写；与横幅对不上时两条都留，别只留一条。
- 报告里的地址/主机名是**本工具看到的目标**，不能替代卡里 `target_host` 的对齐。

## 已知坑

- **整段扫描会出现假 `filtered`**：批量扫多个端口时个别端口报 `filtered`，单点复测却是 `open`。
  要下结论就单点复测，不要把批量结果当终局。
- **目标侧防火墙掩盖可达性**：`filtered` 是环境前提造成的，不是「服务不存在」。
- **来源位置决定结论属于谁**：同一条命令从不同跳发出，回答的是不同的图事实；位置记录必须随证据保存。
- **别把 `-sV` 的输出当身份**：它给的是线索，产品身份要有原文支撑。

## 引用它的技能卡

- `pre.nmap_tcp_probe` —— 有向可达性观测，XML 解析。
- `pre.service_version` —— 服务产品与版本；标识不可读时退到应用层响应路由（见 `http-client.md`）。
