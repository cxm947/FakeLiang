# netexec —— 凭据有效性与一次性远程命令

## 这个工具能回答什么

- **一组凭据在某个目标上有没有效**：协议前端（smb / ssh / winrm）做一次真实登录尝试
  （`pre.credential_valid`）。
- **用一次凭据在目标上执行一条命令**：例如关掉防火墙并回读（`exploit.netexec_firewall_off`）。

它把「连得上」「认证过」「执行成功」三件事打在同一份输出里，读的时候要分开。

## 调用形状

登录尝试（明文与哈希走不同参数）：

```sh
netexec smb <target_host> -u <username> -p <secret_ref>
netexec smb <target_host> -u <username> -H <secret_ref>
```

经 smbexec 执行一条命令（示例：改防御状态并回读）：

```sh
netexec smb <host> -u <user> [-d <domain>] <credential_args> --exec-method smbexec \
  -x 'netsh advfirewall set allprofiles state off'
```

## 输出怎么读

- `[+] ...` / `[-] ...` 是**这次尝试**的结论；同一份输出里的协议行给出目标身份。
- 目标自报主机名与图里的目标要对得上：名字对不上的「成功」属于别人。
- 认证成功但执行被拒（权限、通道、策略）——这是两种不同的结论，不能读成「凭据无效」。
- 登录尝试会成为目标上的计数量：**计数变化是工具的真实行为**，如实记录，不要粉饰成「什么都没发生」。

## 已知坑

- **哈希与口令参数不能互换**：拿哈希套 `-p` 只会拿到认证失败，那不是凭据无效的证据。
- **别把 `-x` 当探索通道**：本仓只接受卡声明的方法与输入，命令要落在卡的方法范围内。
- **一次性执行会改状态**：删除/关闭类动作要声明副作用与还原要求，回读是判定依据。
- **失败原因要留原文**：把「连不上」「认证失败」「执行被拒」压成一句「失败」会丢掉全部可判读信息。

## 引用它的技能卡

- `pre.credential_valid` —— 一次登录尝试，判定凭据在目标上的有效性。
- `exploit.netexec_firewall_off` —— 经服务管理器/主机管理接口改防御状态并回读。
