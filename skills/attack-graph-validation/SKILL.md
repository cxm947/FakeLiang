
# Attack Graph Validation Skill

Use this skill when the user asks to validate an authorized lab attack graph generated by MulVAL or MAVO.

This skill is a thin operating procedure over the local project. It should not replace the project's scripts, schemas, registry, executor, evidence store, or report generator.

## Workflow

1. Confirm the task is scoped to an owned or explicitly authorized lab.
2. Locate the input attack graph.
3. Run the Graph-to-Step Projector to create `action_graph.json`.
4. Run Attack Step Semantics to enrich the steps.
5. Match enriched steps against the Skill Registry (`skills/registry.json`).
6. Generate a dry-run validation plan.
7. If execution is requested and authorized, call the controlled executor interfaces.
8. Save evidence for every attempted step.
9. Generate a report only from stored evidence.

## Boundaries

- Do not generate free-form attack commands when a registered skill exists.
- Do not invent missing evidence.
- Do not treat skipped, blocked, or failed steps as successful.
- Do not expand targets beyond the supplied authorized scope.
- Prefer deterministic scripts and structured schemas over ad hoc model reasoning.

## 读取时机

- 方法卡（`skills/<card>/SKILL.md`）：每张卡只回答“这个方法能不能证明它的目标事实”。卡里的 `何时用 / 怎么做 / 怎么判`（+ 可选 `异常与恢复`）就是本步的执行依据。
- 卡外的共享文本：执行纪律与本步执行依据见 `src/skills/templates/execution_rules.txt`；工具用法见 `skills/_tooling/`。
- 规范与契约：写作与内容去向见 `docs/product/skill_authoring.md`；卡加载、摘要与消费链路见 `docs/product/card_runtime_contract.md`。
- 判词：只用 `pass / unsatisfied / uncertain`。完整且绑定正确的回执**明确否定**目标事实 ⇒ `unsatisfied`；缺证据、绑定不明或权限不足 ⇒ `uncertain`；“命令跑过了”不能代替事实成立。
- 会话交付必须有**实际登记与随后观察**；只完成命令回显不能声称会话交付。
