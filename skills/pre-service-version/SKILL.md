# 指定端口的服务身份与版本检查

## 何时用

核对指定端口实际服务是否符合 expected_service；仅在任务明确要求 expected_version 时核对版本。端口开放、服务身份、版本达标分别判断，版本不证明问题可触发。
目标、端口、期望服务取任务；session_ref 只指运行层已有会话，不允许自行重连或换位置。平台、工具、HTTP 基址和可引回执由运行层提供；服务名与图中声明不是证据。
卡挂在被检查的 AND 步骤上；when.technique 若声明指该步骤 job_id，当前为空不补探测方法编号。check_shape=network_service 只描述检查类型，不证明服务存在。

## 怎么做

按已知协议与现有工具选择一次观察，不要求先扫描再访问页面。服务未知且有 nmap 时做单端口版本探测：

~~~text
nmap -Pn -n -sT -sV --version-light --reason -p {port} -oX - {target_host}
~~~

核对目标、端口、状态与识别内容；非标准端口不按号码猜服务，端口表标签与实际响应分开。版本缺失就记未观察到，不从系统、产品名后缀或常见安装包补版本。

HTTP 已知且有运行层基址时，用 http 动作读取相关页面或接口，保留实际对端、路径、状态、相关响应头、解码状态和身份正文原文；摘要不冒充响应。
scheme、地址、端口沿用基址，不按端口惯例生成 target_url。TLS 失败不静默降级；客户端不支持时报告限制，或选本卡允许且运行层已有的方法。跳转到未声明对象就报告边界，不跟随后把结果记给原目标。

Redis 等明确应用协议使用已有客户端只读标识；确认 Redis 协议且有访问材料后，读取 INFO server，从完整 RESP 响应核对 redis_version。
NOAUTH、认证拒绝或保护模式只说明查询限制，缺版本不等于产品不符；不写配置、不保存、不上传、不改认证设置。

用 python3 或已有解释器组织协议交互时，经允许的 cmd/tool 提交并遵守载体与长度限制。不假定一次 recv 已完整，按协议边界识别消息；预算沿用运行层，不另设秒数、缓冲阈值或重试旋钮。
没有协议完整性证据，缺字段只能记未确认。截断或解码失败须说明保留范围；可见正向片段只支持自身，不能据缺失内容断言不存在。工具留存的原字节可供核对，重解码、转义或加工文本不冒充当前回执逐字引文。

**一次答复只给一个动作，一次调用只选一个已确认适用的观察方法，不在该调用内换模板追加查询。**
读原文后仍可决定是否补针对性观察；针对性观察另起下一次调用，只回答未决条件，不把平台或协议分支当作必须顺序执行的步骤。不提交 actions 批次，不把独立协议查询塞进长命令。缺工具或材料就报缺项，不猜访问材料。

## 怎么判

- pass：本次正确端点的实际响应支持 expected_service；若要求 expected_version，还须有同一产品的明确版本原文并满足条件。无版本要求不加门槛。
- fail：同一判定层级的明确服务身份与要求互斥，或明确版本违反条件；必须引用反证。没有 banner、查询被拒、响应不完整都不是反证。
- uncertain：协议/身份不明、字段缺失、工具失败、TLS 失败、对象绑定不足或观察冲突。服务存在而版本未确认须分别说明，不能把部分观察升级为全部满足。
- Server 响应头可能只是代理或 Web 服务器，不能直接证明后端应用及版本；标题、路径、Cookie 名也不单独证明完整产品身份，须说明证据层级。
- open、HTTP 200、退出码 0、SUCCESS、请求中自填产品名都不单独证明服务与版本匹配。

用引擎 finish 形状分别说明身份、版本条件与证据。引文逐字取本次允许回执；unknown、已 abandon、其他节点记录不补作证明。无原文就写 uncertain，不抄期望值充观察值。
